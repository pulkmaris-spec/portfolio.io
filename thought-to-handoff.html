A Dynamic Design Process - From Thought to Hand-off

A walkthrough of my process for designing "to-do", a task organiser landing page, from first wireframe to a fully re-skinned second version. Covering grid systems, style guides, and how I structure files so re-skinning takes minutes, not days.

Digital product

The brief was to design a landing page for a task organiser app, "to-do". To ground the design in something real, I selected an existing task management app design from the Figma Community as my starting point. It provided the primary inspiration for both the colour palette and the overall theme of the page.

The brief also called for two distinct "skins" of the same landing page, so I designed two variations and built the landing page with an easily adaptable styleguide: a light version with a friendly feel aimed at everyday customers, and a dark version with a more mature look aimed at a B2B audience.

Light mode and dark mode landing pages, side by side

Wireframes & grid

After settling on the type of product, I built wireframes for mobile and desktop at the same time rather than one after the other. For consistency I used a 1440px width for desktop and the iPhone 16 dimensions (393 × 852) as the base for mobile.

I set up a vertical grid system focused on keeping side margins consistent, which made the layout cleaner and much easier to scale across screen sizes.

Following the page structure: Header, Hero, Benefits, Features, Testimonials, Get in Touch, and Footer, I built out text and image placeholders using Figma's Auto Layout. Every time I finished a section for one screen size, I immediately built its counterpart for the other, which kept mobile and desktop moving in lockstep instead of one falling behind.

Wireframes for desktop and mobile, built in parallel

Style guide

With the wireframes in place, I turned the placeholder text into defined text styles which consisted of a dedicated set for each device, so hierarchy and clarity held up across screen sizes. Once those were established, I swapped every placeholder in the wireframes for the new styles, so the final design phase would only ever need content adjustments, not structural ones.

Text styles

For colour, the goal was a palette that felt versatile enough to re-skin later. I built Primary, Secondary, and Tertiary colours, a Neutral tone for the background, and Purple and Pink accents — ten colours in total, structured to support and unify the page's final look.

Colour palette for light mode

There were two ways to make the style guide flexible enough to re-skin: use variables within the file to manage reusable styles, or set up a style guide and duplicate the file to re-skin the design. I went with the second approach since my personal Figma account is on the free plan, which doesn't include the variable modes needed to build the first system.

Buttons, icons and effects

With colours and text styles settled, I moved on to the button components, designed separately per device so each could carry the right visual weight and usability for its platform, and to show how CTAs could adapt across screen sizes.

Desktop and mobile button variations

Alongside that, I built a compact icon library to keep the interface consistent, and defined a small set of effects such as drop shadow, inner shadow, layer blur, and background blur that I could apply across the page. Together, these pieces reinforced one cohesive, flexible visual style.

Compact icon library

Final design

For the final design, I took the wireframe foundations and applied the style guide's colours, dropping assets into pre-built card components for each section. This is also where I designed the final footer and top navigation, so every layout felt consistent and complete.

Footer and navigation

To add visual depth, I brought in accent colours from the palette and built gradients with reduced opacity and layered effects — an approach that made those styles easy to update later when re-skinning the page.

Finally, I organised the final designs into separate pages so that, in prototype mode, each could be viewed at its correct screen size.

Final prototype for light mode

Second skin

Once the first version was finished, I duplicated the file to build the second variation which was a dark, B2B-facing version. I started by updating the colour palette, then adjusted the text styles, and finished by replacing the assets.

Because the style guide and components were already well-structured, updating the colours and text styles (not counting the asset changes due to the different target audience) took less than 30 minutes. That turnaround was the whole point of investing time in the style guide up front.

Final prototype for dark mode

External tools

A few external resources supported the process: a UI icon library and a product design library, both sourced from the Figma Community (the icon library for general interface icons), and the product design library for the four core screens of the task management app. I also used ChatGPT throughout, mainly to explore different directions for the product, get additional suggestions on the brief, and sharpen content I'd already written.

Reflections

What stuck with me most from this project was how much a well-built style guide pays off later. Because the text styles, colours, and components were structured properly from the start, re-skinning the entire landing page for a completely different audience took minutes rather than a full redesign, proof that the groundwork in the early stages is what makes the later stages fast.
